# Changelog

This project versions three surfaces together under semver — the Python library, the MCP tool set,
and the receipt format. See `docs/VERSIONING.md`.

## Unreleased
- combinatorics, periodic_table, atomic, number_theory, wordcraft and operations_research read every claimed or input integer as the exact integer it writes, never by dropping its fraction or taking a bool for one. They read through mathematics' two readers, now one shared module (`verifiers/_integer.py`): an input with a fraction, a bool or other text reads SYSTEM_ERROR, naming the field, and a claimed value with a fraction stands as written and reads BROKEN. So P(5,2) claimed 20.9 and iron claimed atomic number 26.5 read BROKEN where they read HOLDS; P(5.5,2) claimed 20, iron claimed 'twenty-seven' or '26.0' and hydrogen claimed true read SYSTEM_ERROR where they read HOLDS, and P(5,2) claimed true where it read BROKEN. A quantum number with a fraction is invalid, so a set with n 2.7 claimed valid reads BROKEN and claimed invalid HOLDS, and m_l true reads SYSTEM_ERROR, as does m_l given as other text, which read invalid. A claimed text with a fraction, which int() refused, reads BROKEN, and a claimed count written '3.0' reads SYSTEM_ERROR, as '20.0' did. Mathematics reads exactly as before, its refusal sentence included. `tests/test_exact_integers.py` holds every case. The benchmark still reads 1796 of 1796 with no false positive and no false negative, and its counterexample count, which `/capabilities` reports from `data/benchmark_last.json`, moves from 954 to 955: the number_theory golden's false spec claims an inverse of 15.5, which int() read as 15, the true inverse of 3 mod 11, so that check confirmed inside a packet that read BROKEN on its other checks, and now it is a counterexample. As with any change to a verifier, every memo entry of these domains, of mathematics and of physics, whose closures now read the shared module, misses once and stays on disk unread.
- A polynomial claim that states its ring and generators can be read. Through mode polynomial, or mode number_theory or a MATH_VERIFY packet holding generators or ring, a claim gives gcd or lcm as a list of two or more polynomial texts, claimed_gcd or claimed_lcm as a text, generators as a list of names and ring as ZZ or QQ, and the answer compares up to a unit: plus or minus one over ZZ, any nonzero rational over QQ, and zero equals only zero. So gcd(x**2 - 1, x - 1) = x - 1, which reads INCOMPLETE as an equality, reads HOLDS with ring QQ and generators [x], as does the claim 2*x - 2, and the gcd of y - x and x - y is x - y and y - x alike with [x, y] or [y, x]. Over ZZ the gcd of 2*x + 2 and 4*x + 4 is 2*x + 2 or -2*x - 2, and x + 1 reads BROKEN. A text must be a polynomial by its form, read on its syntax tree before anything is evaluated: the generators, numbers, signs, sums, products, division by a number and powers to a whole number. A missing field, another ring, a symbol outside the generators and any other text read INCOMPLETE and say what to state, so a text whose value is a polynomial and whose form is not reads INCOMPLETE too, as exp(0)*x does. The verify tool's mode enum gains polynomial, so the tool hash `/capabilities` reports moves, and there is no ninth tool. No benchmark case reaches this mode, so the moat and `tools/unreached.py`'s count do not move and `MEASURED.md` says so.
- Mode number_theory reads a number as the exact integer it writes: an int, a finite float with no fraction or a text of an integer, and never a bool, a fraction or anything not finite. So {factorial: 5.9, claimed_factorial: 120} reads SYSTEM_ERROR where it read HOLDS, as do {gcd: [12.7, 18], claimed_gcd: 6}, {gcd: [true, 2], claimed_gcd: 1}, {gcd: '24', claimed_gcd: 2}, which was read digit by digit, {is_prime: 17, claimed_prime: 'false'}, since claimed_prime must be a real boolean, a binomial or modulo of more than two values, and {gcd: [12, 18], claimed_gcd: 6, lcm: [4, 6], claimed_lcm: 99}, since a spec holds one claim. {gcd: [12, 18], claimed_gcd: 6.9} reads BROKEN where it read HOLDS, with the computed value in the data, since it is a number the answer is not. The domain number_theory has its own reads and is not closed: {gcd_a: 48.7, gcd_b: 36, claimed_gcd: 12} still reads HOLDS through NUM_VERIFY, and `MEASURED.md` names the rest. As with any change to `verifiers/mathematics.py`, every mathematics memo entry misses once and stays on disk unread. A verdict no longer rests on a value the claim never bound, on a side of a limit the claim never named, or, in mathematics' number_theory mode, on a fraction dropped from a number; and a polynomial claim that states its ring and generators can be read.
- A limit is read from both sides, and at a finite point only for a form on an allow-list. Limit mode takes an optional `direction`, '+', '-' or '+-', and absent means both: Abs(x)/x at 0 = 1 reads BROKEN where it read HOLDS, Abs(x)/x at 0 dir + = 1 reads HOLDS, sides that disagree read BROKEN for every claimed value with left and right in the data, and 1/x**2 at 0 = oo reads HOLDS where it read BROKEN, since a value compares by equality before any subtraction. limit and Limit answer through the same helper and refuse anything else, so limit(Abs(x)/x, x, 0) = 1 reads INCOMPLETE. Claims that now need a stated side: a function that leaves the reals on one side where sympy's sides disagree, as Abs(x)*(1 + sqrt(x))/x at 0 = 1. sympy's sides can agree and be wrong, as on 1/(exp(acot(x)) - exp(pi/2))**2 at 0 = oo, so off the list a limit at a finite point reads INCOMPLETE, true ones with the false and even with a stated side: x*sin(1/x) at 0 = 0 and x**x at 0 = 1 read HOLDS before this, and tan(x) at pi/2, floor(x) at 1 and sin(1/x) at 0 lose their readings. The list holds plain real numbers alone, settles each value by a read and never by sympy's is_zero, and keeps a cut out of a cut, so x + log(2) at 0 = log(2), anything holding I and anything at a point past 10**6 read INCOMPLETE. The list reads every sum, call and non-integer power for a hidden zero, and a read must keep its digits, so a zero that is 0 everywhere is off it wherever it stands: (sin(a)**2 + cos(a)**2 - 1)/x**2 at 0 = 0 and ((a + 1)**2 - a**2 - 2*a - 1)/x**2 at 0 = 0, which read BROKEN though each is true, read INCOMPLETE, as do log(1 + x**7)/x**7 at 0 = 1, sin(x**70) at 2 = sin(2**70) and x + exp(exp(x)) at 50 = 50 + exp(exp(50)), which read HOLDS. A form with a pole has every other part rational at the point, so exp(x)/(x - 1)**2 at 1 = oo, (exp(x) - E)/(x - 1) at 1 = E and sin(x)/(x - a) at b = sin(b)/(b - a) read INCOMPLETE where they read BROKEN or HOLDS, and a form that cancels more than 10 digits at the point is off the list, so cosh(x) - sinh(x) at 100 = exp(-100) reads INCOMPLETE where it read HOLDS. A non-integer power of a power is off the list at any finite point, so sqrt(x**2) - 1 at -1 = -2, a false HOLDS, and sqrt(x**2) at -2 = 2, a true one, read INCOMPLETE, and (sqrt(x**2) - 2)**2/(x + 2)**2 at -2 = 1 where it read BROKEN. Abs and sign are placed by where they stand and never by value, so Abs(x)/(Abs(x) + x) at 0 dir - = 0 reads INCOMPLETE. Limit reads the function simplified at oo and -oo, as it did, so a finite reading there stands as before in every spelling. An infinite reading confirms only in a rational function with rational coefficients at a rational point, where zero is decidable: 1/x**2 at 0 = oo and 1/(x - 1/3)**2 at 1/3 = oo read HOLDS where they read BROKEN. Anywhere else a claim equal to one reads INCOMPLETE, true ones with the false, where it read BROKEN: log(x) at 0 dir + = -oo, 1/sqrt(x) at 0 dir + = oo, exp(1/x**1000) at 0 dir - = oo, 1/x**2 + sin(x) at 0 = oo, 1/(x - sqrt(2))**2 at sqrt(2) = oo, a/x**2 at 0 = oo*sign(a) and x at oo = oo. x at oo = 5 stays BROKEN. A limit-mode claim that spells neither limit nor Limit moves by this only where a reading equals it, so (cosh(x)**2 - sinh(x)**2 - 1)*x at oo = 0 stays a false BROKEN. Limit refuses an infinite reading at any point, and limit where the claim wrote the infinity, so Limit(log(x), x, 0) = 5, limit(x, x, oo) = 5 and x at limit(x, x, oo) = 5 read INCOMPLETE where they read BROKEN, and 1/x at limit(x, x, oo) = 0 where it read HOLDS. A claimed limit inside an AccumBounds reads INCOMPLETE. A decimal in a limit reads as what it writes, so sign(3*x - 0.3) at 0.1 = 1 reads BROKEN where it read HOLDS. In prose, right-hand and left-hand at the head of a claim, the start of the text after at most the or a, state the side, with or without side after them, as do right side and left side, and one-sided and any other word naming a side directly before limit of extract nothing, with any dash. Anywhere else prose reads no side and writes direction 'unstated', read as both sides: where they disagree a claim equal to one side reads INCOMPLETE, naming direction, and a claim equal to neither reads BROKEN, so the limit of e^(-1/x) as x approaches 0 is 0, a false HOLDS, and for positive x, the limit of e^(-1/x) as x approaches 0 is 0, a true one, read INCOMPLETE, and the limit of e^(-1/x) as x approaches 0 is 5 stays BROKEN. Where the sides agree nothing moves. The list is measured by a slow sweep, not proved, and MEASURED.md gives its counts. A verdict no longer rests on a side of a limit the claim never named.
- A pole written two ways reads as one, on proof. The equality guard compares pole bases as written, so 1/(y + x) = 1/(x + y), 1/(x - y) = -1/(y - x), 1/(2*x - 2*y) = 1/(2*(x - y)), 1/(x*y) = (1/x)*(1/y), 1/(x**2 - y**2) = 1/((x - y)*(x + y)) and 1/(x**60 - y**60) = 1/((x**30 - y**30)*(x**30 + y**30)), each true, read HOLDS where they read BROKEN. The guard itself is unchanged and there is no new refusal: a compare can only lift its BROKEN, and only on proof, for a rational function with rational coefficients written out on each whole side, so a term that cancels and a call that evaluates away cannot hide a pole from it. It proves by multiplying and never by factoring: each side's unmatched factors are multiplied out sparsely and the two products must be one polynomial up to a nonzero rational. A claim it cannot prove keeps its BROKEN, the true ones with the false: a float, a non-rational constant, a non-polynomial base, anything off the list, a claim past the term bound, or a power's multiplicity the written factors drop. So x/x = 1 and (x**2 - 1)/(x - 1) = x + 1 do not move, and 1/(x**2 - 2*x*y + y**2) = 1/(x - y)**2 and 1/simplify(y + x) = 1/(y + x) stay BROKEN though each is true. The exact-decimal and stated-precision paths confirmed without reading the guard, and now every confirm reads this answer: 0.1*x/x + 0.2 = 0.3 reads BROKEN where it read HOLDS, as does x/x*3.14159 = 3.14 stated to 3.14, and so does a pole in a term 0 multiplies inside a window, so a removable singularity no longer reads HOLDS by arithmetic or inside a window. A confirmed equality keeps its plain detail when a side is no rational function of its free symbols or past 500 estimated terms, and when the proof lifted it.
- A verdict no longer rests on a value the claim never bound. gcd and lcm are read over exact rationals alone, as the fold of sympy's two-argument function, so a third number is never read as a generator and a sequence of one reads as its absolute value: gcd(12, 18, 5) = 1 and lcm(4, 6, 5) = 60 read HOLDS where they read BROKEN, and = 6 and = 12 read BROKEN where they read HOLDS. A gcd or lcm of anything else, a Poly or degree on generators nobody named, and a degree or Poly with a free symbol inside Sum, Product, Subs, limit, solve, solveset or a definite integral, or in modes system, limit and solve, now raise `UnboundRefused` before the call runs and read INCOMPLETE in every mode, with a reason that says what would bind them. So Sum(gcd(k, 12), (k, 1, 4)) = 4, Subs(gcd(x, 12), x, 6) = 1, gcd(x, x + 2) = 1, gcd(12.0, 18.0) = 1, gcd(y - x, x - y) = x - y, degree(Poly(x**2 + y**3)) = 2 and degree(x**2 + 1, x + 1) = 0 no longer read HOLDS, and a true polynomial claim such as gcd(x**2 - 1, x - 1) = x - 1 reads INCOMPLETE with them. A passing check beside an unbound one no longer carries a packet to HOLDS, and an unbound step never hides a false one in a chain or a system.
- A process that freezes is restarted, whatever froze it: `serve` tells systemd `WATCHDOG=1` by the plain `NOTIFY_SOCKET` protocol only after its own read of `/health` answers, and `deploy/nh-v3.service` sets `WatchdogSec=150` with `NotifyAccess=main`, long enough that two failed reads survive and a busy engine, which answers late, is not killed for it. The memory wall stands outside the cells: `MemoryMax=1G` with `OOMPolicy=continue`, from the measured PSS of the front, the forkserver and four cells. `deploy/install.sh` keeps a record of the previous commit and unit until the service has held past WatchdogSec with MainPID and NRestarts unchanged, and any failure, each `set -e` exit among them, checks that commit out in place, restores the unit, restarts and reports `/health`. Nothing moves or deletes data/ or .env on any exit, so a seal written during the hold survives, and a failed gate leaves `data/benchmark_last.json` as it was. Any failure on a cell's pipe ends that cell and reads as ERROR, and a cell does not outlive its forkserver.
- A read the window could not stop no longer stops the engine. `serve()` runs every read in a worker process the front can kill (`concordance.cells`), so one bad read costs one cell, the rest of the engine keeps answering, and it comes back by itself. A stuck cell is killed at the window and sheds to the same ERROR as before; a used cell retires after `CONCORDANCE_CELL_READS` reads and an idle one after `CONCORDANCE_CELL_IDLE_S` seconds, new cells fill the space, and never more than `CONCORDANCE_VERIFY_WORKERS` are alive. A cell that dies, cannot start or sends what cannot be read is ERROR, never a verdict. Cells read and write nothing, so seals, the ledger and the CAS stay in the front, and sympy never enters it: a sympy value leaves a cell as the string JSON prints for it, and a numpy value leaves as it is. The moat reads the same through cells on all 1,796 cases, 0 false positives and 0 false negatives. Library use stays on its threads and importing starts no process. As with any change to `derivation.py`, every domain's memo entries miss once and stay on disk unread. Measured in `MEASURED.md`.
- A claim's stated precision belongs to the claim. A literal written beside a claim sets its window only when it is the number the claim states, compared in the claim's own unit up to float representation; any other literal can only narrow, and the data says it was not the claim's, so a structured request can no longer hand a false claim a window it never stated. `window_for` now requires the claimed value, every reader goes through that test (`base.literal_is_claim`), and the hedged flag widens only a literal that passed. The equation extractors state the value plus its residual over the slope against the value itself, wherever a float can carry that sum; where it cannot, the residual stands alone with no literal. `band()` never counts a value that is not finite as inside: a finite recomputed value against a claim not finite is a mismatch, a recomputed value or a window not finite is an error, and every consumer of a band result keeps an error an error, so could-not-compare is neither a pass nor BROKEN. The memo fingerprint of each domain now hashes the import closure of its verifier and of the runner, plus `derivation.py`, so a change to any module a verdict reads moves the key: every domain's entries miss once and stay on disk unread.
- The parser refuses a value with no meaning at the node that built it: anything holding zoo, nan or AccumBounds or an infinity nobody wrote, so a later step cannot collapse it into an ordinary number; a written oo stays legal. In a MATH_VERIFY or PHYS_VERIFY packet a refused text removes only the passing checks beside it, so a false or erroring check still reads. In mathematics' numeric mode a value not finite as a float passes no comparison, and a finite value against a claim not finite reads as a mismatch. The memo's fingerprint for mathematics and for physics now covers verifiers/mathematics.py, so a verdict stored under older source is not served: each such entry misses once and stays on disk unread. scribe reads each recompute's composite verdict, so a claim refused or errored in any step reads UNCHECKED, and neither reads CONVERGED nor leaves its writer clean. Deferred objects and the other forms the run names stay open.
- Security: text from a request is never evaluated. One parser, `mathematics.parse_expression`, reads every expression by walking Python's ast and building sympy objects, so no request text reaches `sympify`, `parse_expr` or any sympy entry that parses a string, in any verifier; a refused text never reads HOLDS.
- Post-quantum durable receipts (`concordance-receipt/3.1`, additive). Beside the Ed25519 COSE
  statement, a receipt now carries `attest.pq`: an **ML-DSA-65** (FIPS 204, module-lattice / Regev's
  LWE) signature over the same canonical record bytes, binding the same `content_hash`. Ed25519 rests
  on a problem a quantum computer breaks; ML-DSA's hardness survives it, so a receipt proves its
  integrity permanently (crypto-agility: both ride together — Ed25519 for today's tooling, ML-DSA for
  permanence). `CONCORDANCE_PQ_ISSUER_KEY` enables it; `docs/verify_receipt.py` reports a `PQ-SIG`
  line and a receipt is "durable" when it passes; `transparency.pq_envelope` + `signing.pq_*` (the
  `cryptography` library's vetted FIPS 204 implementation — never rolled); RECEIPT_SPEC §2d. The
  golden receipt and conformance suite now pin the PQ signature too.

## 3.0.0a1 — 2026-10-24
- Receipt format named and pinned as an open standard, `concordance-receipt/3.0` (the version rides
  in the attestation's `spec`). The COSE_Sign1 statement now carries the registered CWT Claims
  header (RFC 9597, label 15) with CWT claims (RFC 8392: `iss` = kid, `sub` = content_hash, `iat`),
  so a SCITT-aware consumer reads it directly; the same verdict is also emitted as an in-toto
  Statement v1 in a DSSE envelope (`attest.in_toto`) for in-toto/SLSA consumers. The record's
  `content_hash` is unchanged. `tools/mint_golden_receipt.py` + `tests/test_receipt_conformance.py`
  validate the committed golden and reject tampered copies with the no-import `docs/verify_receipt.py`.
- Packaging and listings prepared (owner publishes): PyPI metadata and `[project.urls]`;
  `server.json` MCP-registry manifest; `docs/RUNBOOK.md` "Publishing and listings (owner only)".
- Harness adapters under `integrations/` (`concordance-integrations`, outside the lean core): a
  DeepEval metric + an autoevals/Braintrust scorer, a LangGraph/AutoGen verify node, and a
  Guardrails validator. One rule — `HOLDS` passes, `BROKEN` fails, everything else abstains (a claim
  the engine could not test is never scored a failure).
- Monte-Carlo fuzz (`tools/mc_fuzz.py`, seeded) over the engine invariants: no false certify, every
  seal re-verifies, bounded time and memory per verify, adversarial text never crashes or seals
  garbage. It found and this fixes a ReDoS: a long digit run made several extractor patterns
  backtrack for tens of seconds. `audit._clamp_digits` collapses any run longer than `MAX_DIGITS`
  (40) before recognition — removing only numbers the engine would never check, so the
  zero-false-positive guarantee is untouched. Pinned by `tests/test_redos_guard.py` and
  `tests/test_mc_fuzz.py`.
- Governance: `docs/VERSIONING.md` (semver across the three surfaces, deprecation policy) and
  `tests/test_public_api.py` (pins the tool set, the receipt spec id, the semver shape of the
  version, and the public exports; fails if the current version has no changelog entry).
- Recall: unit-anchored slot-fillers for Newton's second law (`x_force_units`) and kinematics
  (`x_kinematics_units`, with m/s-vs-m/s² lookaheads) reach claims the word-order regexes miss, any
  order, each slot exactly once — recall grows, 0 false positives unchanged.
- Interchange: `transparency.agentledger_pob` maps a receipt to the AgentLedger proof-of-behavior
  shape (`payload_hash`/`result_hash`/`prev_hash`, signed by the record's COSE_Sign1, chained on the
  engine's ledger); `seal_fetch` carries it at `attest.agentledger`. RECEIPT_SPEC §2c.

## 3.0.0a0 — 2026-10-23
- Core carved from v2 (`concordance-2`): 32 top-level modules, 8 MCP tools, stdlib HTTP API; the .org
  application (`witness`) calls it over HTTP and registers its own verifiers via entry points.
- Coverage: compound sentences report the unchecked clause; slot-fillers quote tight spans.
- Packet schemas generated for every domain; `SCHEMA_ERROR` names the field and its nearest valid name.
- `public_finance` verifier (amortization with interest-only prefix, issuance gross-up, ad valorem,
  depreciated value, abatement ladder, PV).
- `concordance.scribe`: many-writer claim matrix, SVD disagreement axis, recompute verdicts, UNDERDETERMINED.
- Benchmark v2.2.0: 1,669 cases over four tiers, 0 false positives; mutation tool.
- `compose.py`: documents as trees of sealed steps (`bind` inputs to earlier outputs), one root hash,
  parents, `/s/<root>?html=1` tree page with whole-chain re-check. Driven by a synthetic memo only.
- License: MIT.
- Transparency: `transparency.py` mints COSE_Sign1 (Ed25519) statements over every served record and logs them
  on Rekor as `rekord` entries (Rekor re-verifies the signature on admission); `attest` rides beside the record
  in `seal_fetch` / `/s/<hash>` and the receipt and tree pages; `python -m concordance keygen`;
  `tools/publish_seals.py` flushes pending entries; `docs/verify_receipt.py` checks hash, signature, log entry
  and Merkle inclusion with no Concordance import; `docs/RECEIPT_SPEC.md`. The v2 in-toto/DSSE `envelope.py`
  and `tools/publish_seal.py` are removed — one statement format, not two.
- Inverted reading — not a truth engine: `band()` / `bound()` in verifiers.base; `refutations` manifest and
  `read` sentence per verdict, sealed into the record; counterexamples (recomputed value, band, off_by) first-class;
  receipt page shows bands; scribe `narrow_way` (eliminated / surviving / [min, max] bracket). 68 verifier
  modules converted (260 checks), verdicts and tolerances unchanged; benchmark reports band coverage (50.6%).
- Context loop closed on every door: `airlock.strip_fields` de-identifies free-text fields in packets and
  documents with one stable map; `reveal_deep` puts context back into the response (never the seal);
  `context` in every verify/discern/scribe result names what travelled and where it was reapplied. Scribe
  writers see only the skeleton; `drafts_revealed` is the user's copy. compose strips title/labels/prose.
- Margin and trace: every band carries `used` (share of tolerance spent); each step a `margin`; each
  derivation a `trace` (OTDR view: distance = depth in `uses`, event = pass | reflection | dark, used, off_by)
  and a `budget` (the worst event), sealed into the gate details and shown on the receipt page.
- `bucket.py` — the smallest bucket: a verdict memo keyed by (packet bytes, domain, engine version, verifier
  source fingerprint); hits are served and labelled on the trail, trace, record and page; errors never memoised.
- `trust` on every HOLDS: Beta(1+FP, 1+n−FP) from `data/benchmark_last.json` (`tools/benchmark.py --record`),
  mean and 95% upper bound on the false-pass rate, in capabilities and the verify response.
- Plugins declare `STRATUM`; the scripture verifier pack (witness/canon) registers as `scripture`, pure.
- `CLAUDE.md`: working notes and the non-negotiables for anyone (or any agent) working in this repo.
